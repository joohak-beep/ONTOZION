ONTOZION

Local-first personal intelligence operating system

Open-source blueprint · English edition

A personal JARVIS that acts quickly without surrendering human authority.

This design combines a local language model, a durable memory and indexing layer, an explicit authority broker, and verifiable device tools. The goal is not to give an AI unlimited power; it is to make everyday computer work fast while keeping the BOSS (the single human owner) in control.

00 · Overview

The control path is deliberately layered: the model proposes, the harness checks, tools execute, and the ledger records what actually happened.

→ →
↓ ↓ ↓
↔ ↔
BOSS is the only owner of irreversible authority. JARVIS can act autonomously only inside explicit, revocable limits.

North star

Replace tedious Windows, browser, and phone work with natural voice and visible results, while preserving privacy and human veto.

Fast path

Use small deterministic tools for routine actions. Reserve deeper model reasoning for ambiguity, planning, and recovery.

Proof path

Every action has a request ID, policy decision, tool result, evidence, and outcome. “The model said so” is not proof.

Purpose: preserve BOSS self-determination

ONTOZION is a BOSS-owned, distributed, mutually learning personal AGI mesh. JARVIS nodes on different computers may question and teach one another, so the BOSS does not need to answer every intermediate question.

Freedom means that the BOSS can understand alternatives, choose, refuse, and revoke. Distributed question rights never grant execution power, administrator access, or permission to rewrite the Constitution.

Public scope

The only representative agent and operating runtime is ONTOZION/JARVIS. No external general-purpose agent runtime is installed, executed, or required. All models, skills, MCP/ACP integrations, tools, learning loops, and verifiers remain inside the JARVIS harness; connected services cannot bypass its Constitution or authority broker.

01 · Constitution

The constitution is a compact policy contract. It is compiled into checks, not left as a prompt that a model may forget.

Ten operating principles

  1. BOSS authority is explicit, scoped, revocable, and never inferred from silence.
  2. Irreversible actions require a fresh approval token, unless a pre-approved narrow policy covers them.
  3. Credentials and secrets are referenced through a vault; they never enter prompts or logs.
  4. Private data and local STT/TTS stay local by default. Cloud voice is a separately visible, per-session choice.
  5. Every tool call is least-privilege, typed, bounded, and idempotent where possible.
  6. Uncertainty causes a pause, a smaller action, or a question; it never silently becomes permission.
  7. Verification follows execution. A successful API response is not the same as the desired state.
  8. Failures are contained, reversible, and recorded. Repeated failure opens a circuit breaker.
  9. Learning may improve suggestions and routing, but cannot rewrite the constitution autonomously.
  10. Human override, shutdown, audit, and data export remain available at all times.

Machine form

Policy becomes schemas, allowlists, risk classes, expiry rules, and post-condition tests.

  "risk": "financial_order",
  "scope": "broker:paper",
  "approval": "fresh_boss_token",

Semantic kernel

Objects and relationships

Stable IDs represent people, BOSS, family members, agents, models, devices, apps, accounts, tasks, skills, capabilities, policies, memories, events, evidence, and outcomes.

Memory projections

One grammar for every tier

Short-, medium-, long-term, and fact-ledger memory all use subject–predicate–object plus time, source, confidence, sensitivity, and expiry. Vectors are search projections, not the source of truth.

Performance rule: Ontology does not mean calling a large LLM for every action. Keep an append-only canonical event store, cache hot relations, compile frequent policy queries, and rebuild vector/lexical/graph projections asynchronously. Meaning stays precise while routine work remains on the fast lane.

CodePlan: local models design, the harness executes

The code-facing protocol is a typed execution plan, not a free-form paragraph.

Reflex lane

Small local SLLM

Classifies intent, links entities, selects a tested skill_id, and emits simple CodePlans with low latency.

Design lane

Strong local open-weight model

Designs complex code changes, refactors, and test plans, but never owns files, shells, or administrator authority.

Teacher lane

Selective cloud model

Critiques a redacted plan when local confidence is low or tests repeatedly fail. It never executes local tools directly.

Coding performance rule: Pre-index the repository and symbols; run independent reads and tests in parallel; serialize writes to the same file; use SLLM or codemods for small changes; and escalate only complex design, low confidence, repeated test failure, or a new architecture to the stronger model or teacher.

03 · Lifecycle

Click a stage to see the expected hand-off. The same request ID follows the work from voice to ledger.

Fast lane

Wake → classify → deterministic tool → verify → report. Target routine actions with low latency.

Deep lane

Plan → retrieve evidence → delegate → simulate → request approval → execute → verify.

Recovery lane

Detect mismatch → stop retries → capture evidence → repair or ask. Never hide a partial result.

04 · Authority

The authority broker is not a second boss and not a second conversational agent. It is a narrow, fast enforcement layer below the constitution and above tools.

Green · pre-authorized

Read local files, summarize, search approved sites, move a window, create a draft, or run a reversible test inside a fixed scope.

Amber · confirm or simulate

Send a message, change a setting, install software, use a credential, or touch an external account. Show the exact proposed action.

Red · BOSS only

Financial orders, irreversible deletion, legal commitments, public publication, new data-sharing scope, and policy changes.

Preflight and requests: Before acting, JARVIS checks the Constitution version, risk/data class, target, capability, expiry, budget, rollback, and policy conflicts. If allowed, it runs; if scope is missing, it sends REQUEST_APPROVAL to BOSS. If it conflicts with the Constitution, it does not run and may only submit PROPOSE_RULE_CHANGE; no rule changes before BOSS approval, re-authentication, a new version, and regression tests.

Agent-loop authority, approval, and execution

A periodic run is an expiring lease, not an unbounded timer.

PROPOSED → PREFLIGHTED → APPROVAL_PENDING → APPROVED/GRANTED
→ SCHEDULED → RUNNING → VERIFIED → EXPIRED/REVOKED/PAUSED/FAILED/KILLED
Loop rule: JARVIS may propose a loop but cannot activate it or widen its scope. The Supervisor rechecks loop_id, interval, maximum runs/budget, target, tools, policy version, expiry, and kill_handle before every iteration. A Worker runs only with a short Authority Broker capability, heartbeat, and timeout; the next iteration is scheduled only after a verified post-condition. BOSS, Broker, or Supervisor can stop it, and a policy change never carries an old lease forward without fresh approval.

What JARVIS may find first

Automate discovery and preparation; bind movement of money to a separate rule.

Discover

Find unused subscriptions, expiring coupons, and points; prepare candidates with fees, family sharing, and conversion conditions.

Recommend

Surface dormant accounts and investment candidates with timestamps, evidence, risks, and alternatives. A model opinion never creates order authority.

Confirm

Account closure, withdrawals, transfers, and securities orders require current records and a BOSS policy check before bounded execution.

Passkey rule: A passkey is public-key/private-key authentication performed by the platform authenticator, not an encrypted password file. The LLM receives an account alias and short capability, never the raw password or private key. Finance tools separate read, draft, and execute; CAPTCHA, MFA, and identity checks are never bypassed.
Performance rule: cache signed policy decisions for a narrow scope and short expiry. Routine green actions take one local check; they do not wait for a large model.
Safety rule: a cached decision cannot broaden scope, survive expiry, or authorize a different target.
Stop rule: unknown actor, changed target, stale token, policy mismatch, or unverifiable postcondition means stop and surface the reason.

05 · Model roles

Use multiple models by role, not by prestige. A local model protects privacy and provides continuity; a cloud teacher can expand capability without becoming the owner.

ModelBest useCannot do alone
Open-weight local LLMPrivate reasoning, retrieval, routine dialogue, offline continuityGrant authority, bypass tools, or rewrite policy
Personal SLLMUser style, procedures, tool schemas, recurring preferences, compact routingInvent permissions or learn secrets from raw logs
Cloud frontier teacherHard cases, critique, synthetic examples, distillation targetsReceive sensitive data by default or directly execute local actions
Verifier models / rulesSchema, safety, factual, and postcondition checksReplace the BOSS or conceal disagreement
Organic learning loop: The personal SLLM owns fast routing and BOSS-specific procedures; the local open-weight model owns private deep reasoning and coding; the cloud model acts as an Architect/teacher for difficult design and critique. Only harness-verified outcomes become skills or training examples, after which the SLLM learns the stable procedure and the local model retains the private context.
Architect caution: A cloud frontier model may provide the strongest design advice, but it remains an external dependency. Send redacted CodePlans rather than D2/D3 memories, secrets, or capability tokens; challenge its output with local models and regression tests. The cloud model cannot rewrite the Constitution, ontology, or BOSS decisions.

Learning loop

Local models collect approved, redacted traces → teacher critiques selected examples → SLLM learns stable procedures and routing → offline tests and canary deployment measure regression → the BOSS approves promotion.

06 · Memory

Memory is a tiered, evidence-bearing system. It should recall the smallest useful context, not dump an entire life into every prompt.

Short-term

Current turn, wake session, active tool results, interruption state. RAM-first, automatically expires.

Medium-term

Current project, recent decisions, open tasks, temporary goals. TTL and user-editable summaries.

Long-term

Stable preferences, procedures, people, places, and lessons. Promote only with provenance and confidence.

Fact ledger

Atomic facts with source, timestamp, confidence, owner, sensitivity, expiry, and contradiction links. A model may suggest a fact; the ledger decides whether it is trusted.

Data classDefault routeExample

07 · Indexing

Fast recall comes from parallel, specialized indexes and a small retrieval budget, not from asking one model to remember everything.

Lexical

Exact names, commands, error strings, and BM25-style search.

Semantic

Embeddings for paraphrases and conceptual similarity. Store model/version metadata.

Temporal

Recent, active, expired, and “as-of” queries with timezone-aware timestamps.

Graph

People, projects, devices, permissions, dependencies, and contradiction edges.

Procedure

Successful tool recipes with preconditions, steps, postconditions, and rollback.

Provenance

Source, consent, sensitivity, confidence, and deletion lineage.

query → classify → parallel retrieve → merge by score + freshness
      → policy filter → small context pack → model → evidence check
Retrieval contract: return citations, confidence, expiry, and why each item was included. If no item clears the threshold, say “unknown” and ask for a source.

Choose on measured task quality, latency, privacy, and license—not on a model label alone. Quantization must be benchmarked on the actual JARVIS workload.

Quantization ladder

Start with BF16/FP16 reference → FP8/INT8 → Q8 → Q6 → AWQ/GPTQ 4-bit only if quality and tool reliability remain within the acceptance budget.

Honesty audit

Probe factual stability, uncertainty, refusal consistency, multilingual parity, censorship or omission patterns, and whether the model admits missing evidence.

Public sources

Qwen3 · DeepSeek-R1 · GLM / ChatGLM · information-suppression audit · AWQ · GPTQ

ONTOZION fit score: Evaluate every candidate on Korean/multilingual dialogue, long-memory retrieval, typed CodePlans, MCP/ACP tool calls, factuality and uncertainty, censorship/omission behavior, quantized latency and memory, license, and harness integration. Do not crown one model globally; route each task to the best measured fit.
Cloud routing and OpenRouter: An OpenRouter CLI/API adapter can make several Architect models easy to compare and lets the harness control an allowlist, fallbacks, and budget. It is not automatically the cheapest path: record actual tokens, the model ultimately served, service tier, latency, retention/region, and quality, then compare with direct provider APIs. OpenRouter is a replaceable Architect gateway, never the owner of the Constitution or execution authority. Models/pricing API · fallbacks · service tiers

09 · Records

The ledger separates intent, authority, execution, evidence, and learning. It is the antidote to “the assistant sounded confident, so it must have happened.”

{
  "request_id": "uuid",
  "wake_session": "scoped-token",
  "intent": {"summary": "draft a reply", "confidence": 0.94},
  "policy": {"decision": "allow", "rule": "green.draft", "expires_at": "timestamp"},
  "tool_calls": [{"tool": "browser", "target": "approved-domain", "status": "ok"}],
  "evidence": [{"type": "screenshot_hash", "value": "redacted"}],
  "outcome": "verified",
  "learning": {"eligible": true, "redactions": ["private_content"]}
}

State machine

proposed → authorized → running → verified or contained_failure

Privacy

Keep raw audio, screen frames, and credentials out of ordinary logs. Store hashes, summaries, and consent references where possible.

Rollback

Every mutating adapter declares a rollback or a clear “irreversible” label before it can be promoted.

10 · Roadmap

Build from measurable foundations. Do not call the system AGI because it can produce a fluent answer; promote it only when the gates pass.

Phase 1 · foundation

Local runtime, vault references, request IDs, constitution compiler, kill switch, audit ledger.

Phase 2 · fast tools

Typed browser, file, shell, and window adapters with postcondition verification.

Phase 3 · memory

Tiered stores, fact ledger, parallel indexes, provenance, TTL, contradiction handling.

Phase 4 · voice and vision

Wake-scoped full duplex, AEC/barge tests, privacy-bounded screen and camera observation.

Phase 5 · learning

Approved traces, teacher critique, SLLM distillation, offline replay, canary promotion.

Phase 6 · resilient autonomy

Failure recovery, provider failover, multi-device coordination, red-team and physical E2E gates.

Release gate: no critical safety regression, no secret leakage, no unverified irreversible action, and real-device evidence for voice, browser, and recovery paths.
Open-source gate: choose a repository license, preserve each model's original license, remove local paths and secrets, and publish only synthetic or redacted examples.
