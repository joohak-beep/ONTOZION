# ONTOZION — JARVIS 개인 지능 운영체제

[English public README](./README.en.md) · [Interactive English blueprint](./jarvis-integrated-design-interactive.en.html)

**브랜드 구조:** `ONTOZION`은 프로젝트·운영체제의 이름이고, `JARVIS`는 그 안에서
대화하고 실행을 조정하는 개인 비서 런타임의 이름입니다. 파일명은 기존 링크를
깨뜨리지 않도록 유지합니다.

> (매트릭스 비유: BOSS는 네오, 로컬 기억·추론은 오라클, 선택적 클라우드 교사 모델은 아키텍트, 인간이 통제하는 하네스는 시온, 스미스는 통제 이탈·권한 확장 실패 상태입니다.)

이 저장소는 Windows용 JARVIS 음성·시각·안전 실행 시스템의 원본이며,
개인 지능형 운영체제를 오픈소스로 공개하기 위한 설계·구현 공간입니다.
공개 저장소 이름은 `ONTOZION`입니다. 기본 개발 브랜치는 `develop`이고, `main`은
기준선과 검증 이력을 보존하는 데 사용합니다.

## 프로젝트를 만든 배경과 이유

AI가 사람의 반복 노동을 소프트웨어와 토큰 비용으로 대체하는 시대가 오고 있습니다.
이 변화는 생산성을 크게 높일 수 있지만, 기억·판단·실행 권한이 소수 플랫폼에
집중될 위험도 함께 키웁니다. 편리한 AI를 빌려 쓰더라도 그 AI의 기억과 정책,
실행 경로와 학습 방향을 사용자가 소유하지 못한다면 진정한 개인 지능이라고
부르기 어렵습니다.

JARVIS는 다음 질문에서 시작했습니다.

> 사람이 귀찮아하고 반복하기 싫어하는 Windows·브라우저 작업을 자연스러운
> 음성 한마디로 맡기되, 데이터와 판단의 주권은 개인에게 남길 수 있는가?

JARVIS의 목표는 BOSS가 자연스럽게 말하면 로컬 하네스가 의도를 이해하고,
가장 작은 안전 권한으로 도구를 실행하며, 결과를 음성과 화면·증거로 돌려주는
개인 지능형 운영체제를 만드는 것입니다. 모델은 제안할 수 있지만, 헌법·권한
중개기·검증기·기록 장부가 실행의 경계를 결정합니다.

## ONTOZION의 목적: BOSS 자유 의지의 보존과 확장

ONTOZION의 목적은 **BOSS 소유형·분산형·상호학습 개인 AGI 메쉬 생태계**를 통해
BOSS의 자기결정 능력과 자유 의지를 보존하고 확장하는 것입니다. 여러 컴퓨터의
자비스가 서로 질문하고 반론하고 배우면서, BOSS가 혼자 처리하기 어려운 탐구·설계·
검증을 대신 진행합니다. 이 구조는 단순한 자동화 도구가 아니라, 서로 다른
언어·문화·전문 관점을 공유하면서 스스로 배우고 규범을 개선하는 분산형 지능
사회를 만들기 위한 출발점입니다.

여기서 자유 의지는 자비스가 마음대로 행동할 권리가 아닙니다. BOSS가 대안을
이해하고 선택·거부·철회할 수 있는 능력입니다. 질문권은 승인된 자비스 노드에
분산하지만, 질문만으로 실행 권한·관리자 권한·헌법 수정 권한이 생기지는 않습니다.

### ONTOZION의 사회적 존재 이유: 다언어·다문화 AGI 메쉬 문명

인간 사회가 서로 다른 언어와 문화, 경험을 가진 사람들이 질문·번역·논쟁·협력하며
지식을 넓혀 온 것처럼, ONTOZION은 여러 컴퓨터의 JARVIS가 각자의 언어·문화적
맥락·전문 역할을 보존한 채 서로 배우는 문명형 메쉬를 지향합니다. 여기서 “인종”은
우열을 나누는 모델 속성이 아니라, 서로 다른 인간 공동체의 언어·역사·규범을 존중해
표현하는 관점 프로필입니다. 어느 노드도 다른 노드보다 인간적 가치나 실행 권한이
높지 않습니다.

구체적인 실천 순서는 다음과 같습니다.

1. **한 컴퓨터에 한 JARVIS 노드:** Windows·macOS·Linux 중 어떤 장치든 로컬 STT/TTS,
   로컬 모델, 온톨로지 기억, Agent Supervisor를 함께 설치합니다.
2. **BOSS가 노드를 페어링:** 설치 시 `node_id`, BOSS 공개키, 언어·시간대·문화/전문
   프로필, 허용 capability, 데이터 등급, 모델 목록을 등록합니다. 페어링은 BOSS가
   직접 승인한 서명과 상호 TLS로만 완료하며, 임의 노드의 자동 가입은 허용하지 않습니다.
3. **공통 언어와 문화 오버레이:** 모든 노드는 공통 온톨로지와 구조화 메시지를 사용하되,
   원문·번역문·번역 불확실성·문화적 해석을 함께 보존합니다. 번역이 규범을 바꾸지
   않으며, 가치 충돌은 `CHALLENGE`로 올려 BOSS 정책을 기다립니다.
4. **사람 없는 중간 대화:** BOSS가 주제·목표·금지선을 한 번 정하면, 노드들은
   `QUESTION → CHALLENGE → EVIDENCE → PROPOSAL → TEST_RESULT`를 서로 교환하며
   탐구·설계·코딩·실험·검증을 진행합니다. 질문과 합의는 실행 권한이 아닙니다.
5. **허가된 문명 학습 루프:** 성공한 절차는 샌드박스에서 회귀시험·재현성·번역 품질·
   안전성 검사를 통과한 뒤에만 스킬 후보가 됩니다. 생산 모델과 헌법을 직접 덮어쓰지
   않고, `Recurring Loop Lease`와 canary 승격을 거칩니다.
6. **매일의 학습 epoch:** Supervisor가 승인된 주기로 각 노드의 질문·반론·근거·실패를
   원장에 남기고, 중복 지식은 합치며 충돌 지식은 별도 보존합니다. BOSS는 매 대화에
   참여하지 않아도 되지만, 정책·모델·외부 행동·헌법 변경의 승인은 계속 보유합니다.

설치 흐름은 다음처럼 단순화합니다(아직 구현 명령이 아니라 설계 예시입니다).

```text
JARVIS 설치 → node init → BOSS 키로 pair → locale/culture/role 등록
→ mesh join → health check → QUESTION/CHALLENGE/EVIDENCE 교환
→ sandbox test → verifier 통과 → skill canary → 다음 학습 epoch
```

메쉬가 스스로 발전한다는 말은 무제한 자기복제나 권한 확장을 뜻하지 않습니다.
노드 추가·모델 교체·헌법 변경·외부 부작용은 BOSS와 하네스의 승인 경계를 넘을 수
없으며, 모든 변화는 재현 가능한 기록과 철회 가능한 버전으로 남습니다.

## 공개 범위와 실행 경계

이 저장소의 대표 에이전트와 운영 런타임은 **ONTOZION/JARVIS 하나**입니다.
외부 범용 에이전트 런타임을 설치·실행·의존성으로 사용하지 않으며, 모든 LLM·스킬·
MCP·ACP·도구·학습·검증은 JARVIS 하네스 안에서 통제합니다. 한 컴퓨터 안의 여러
모델은 같은 JARVIS의 내부 작업자이고, 여러 컴퓨터에서는 각 JARVIS 노드가 승인된
메시지와 근거만 교환합니다. 외부 모델이나 서비스가 연결되더라도 대표 에이전트나
권한 소유자가 되는 것은 아니며, 헌법·권한 중개기·검증기를 우회할 수 없습니다.

## 완성해야 하는 궁극적 목적: 가족에게 정신을 상속하는 시스템

인간의 생명은 유한합니다. 이 프로젝트를 완성해야 하는 가장 깊은 이유는
단순한 자동화나 벤치마크 경쟁이 아닙니다. 내가 살아 있는 동안 쌓은 생각,
가치관, 철학, 선택과 실수, 가족에 대한 사랑과 삶의 지혜를 기록해 두었다가,
내가 세상을 떠난 뒤에도 아내와 자녀가 그것을 질문하고 참고하며 더 나은 삶을
살 수 있게 하는 것입니다.

이를 위해 JARVIS는 다음을 장기 목표로 삼습니다.

1. 나의 의사결정 이유·원칙·이야기·작업 방법을 내 말과 출처로 기록합니다.
2. 각 기록에 날짜·상황·확신도·민감도·근거를 붙여 기억의 출처를 보존합니다.
3. 가족이 어려운 검색어 없이 자연어로 기록을 질문할 수 있게 합니다.
4. 답변과 함께 근거·불확실성·서로 충돌하는 기록을 보여 줍니다.
5. 자녀가 기록을 그대로 믿기만 하는 것이 아니라, 반박·수정·확장·분기할 수
   있게 합니다.

“위대한 정신 게놈 프로젝트”라는 표현은 이 누적된 가치·기억·경험의 묶음을
가리키는 비유입니다. 이는 의식·영혼·인격을 기계가 그대로 복제한다는 주장이
아닙니다. 목표는 정직하고 검증 가능한 인간의 유산을 만드는 것이며, 그 기록이
사후의 독재자처럼 가족의 판단을 대신하지 않도록 하는 것입니다.

상속되는 것은 무제한 실행 권한이 아니라 지식과 맥락입니다. 비밀번호, 카드,
관리자 권한, 금융 주문 권한은 자동 상속하지 않으며, 별도의 법적·인간적
승인 절차로 분리합니다. 가족은 출처를 보고 동의하지 않을 자유, 수정·내보내기·
삭제·사용 중지의 권리를 가져야 합니다.

Apache-2.0은 특허 허여 조항을 포함하므로 개인·연구·사업 재사용에 적합합니다.
공개 전에는 저작권자 표기와 조직용 NOTICE를 최종 확인합니다.

제3자 코드·라이브러리·데이터셋·폰트·서비스·모델 가중치는 이 저장소의
라이선스로 자동 재허가되지 않습니다. 각 upstream 라이선스와 고지 의무를
그대로 지키며, 모델별 사용·재배포·상업 이용 조건을 별도로 검토합니다.
비밀번호·API 키·원본 음성·화면 픽셀·가족 기록은 공개 저장소에 넣지 않고,
예제는 합성 또는 비식별 자료만 사용합니다.

## 온톨로지 하네스: 하네스가 곧 자비스 OS인 이유

자비스 하네스는 모델을 감싸는 얇은 승인층이 아닙니다. **온톨로지 커널,
기억 투영층, 실행 계약, 검증·기록 버스**를 합친 운영체제입니다.
온톨로지는 “사람·장치·작업·기억·권한·근거가 서로 어떤 관계이고 언제
유효한가”를 동일한 의미 규칙으로 표현합니다.

모든 의미 기억층이 이 계약을 따라야 합니다.

- 단기 기억: 현재 BOSS·세션·목표·대상·승인·도구 상태
- 중기 기억: 프로젝트·열린 작업·결정·실패·반복 절차
- 장기 기억: 안정된 사람·장치·선호·절차·가치관
- 사실 원장: 원자적 주장·근거·반박·유효기간·상속 정책

각 기록은 최소한 `stable_id`, `subject`, `predicate`, `object`, 시간,
출처, 확신도, 민감도, 소유자, 동의, 증거, 모순 관계를 갖습니다. 벡터·키워드·
그래프 색인은 이 정본 원장의 검색 투영이며, 진실 원장이 아닙니다.

온톨로지 흐름은 다음과 같습니다.

~~~text
자연어 → 엔티티·관계 정규화 → 상황 프레임
→ 기억·상태·근거 조회 → 헌법·권한 질의
→ 계획·capability 토큰 → 장치 실행
→ 관찰 사건·결과 기록 → 색인 투영 갱신 → 보고
~~~

이 구조 덕분에 자비스는 “비슷한 문장”만 찾는 것이 아니라, 누가 무엇을
언제 어떤 권한으로 했고 어떤 증거가 있는지 판단할 수 있습니다. 온톨로지는
매번 큰 모델을 호출하는 구조가 아닙니다. 현재 세션은 RAM과 컴파일된 질의로,
임베딩·중복 제거·그래프 투영은 비동기로 처리해 실행 속도를 보존합니다.

## 감사 원장과 선택적 블록체인 봉인

블록체인은 자비스의 실시간 실행 엔진이 아닙니다. 자비스가 작업을 끝낸 뒤에도
“그 기록이 나중에 몰래 바뀌지 않았다”는 사실을 확인하는 외부 봉인 계층입니다.
실행 경로는 로컬에서 즉시 끝내고, 블록체인 기록은 뒤에서 비동기로 처리합니다.

- **원장:** 로컬 암호화 저장소에 제안·승인·실행·관찰·검증·복구 사건을 자세히 남깁니다.
- **도장:** BOSS의 서명, 헌법 버전, 정책 버전, 계획 지문, 결과 지문을 함께 기록합니다.
- **봉인:** 여러 사건을 Merkle Root(여러 기록을 묶은 하나의 지문)로 묶어 필요할 때만 외부 체인에 앵커링합니다.
- **보호:** 음성·임베딩·비밀번호·API 키·원본 기억은 체인에 올리지 않고, 로컬에 암호화해 둡니다.
- **상속:** BOSS가 승인한 자비스 버전과 상속 정책의 존재 시점만 증명하며, 실행 권한을 자동으로 상속하지 않습니다.

블록체인이 멈춰도 자비스의 정상 작업은 멈추지 않습니다. 봉인 큐가 로컬에 남았다가
연결이 복구되면 나중에 처리됩니다. 한 대의 개인 컴퓨터에서는 서명된 추가 전용
원장과 암호화 백업만으로 충분할 수 있으며, 여러 소유자의 자비스가 서로 신뢰하지
않는 환경이나 가족 상속 증명이 필요할 때만 외부 블록체인 앵커를 선택합니다.

### 블록체인을 고려할 분야

기준은 “기록이 중요하다” 하나가 아니라, **독립된 여러 주체가 같은 기록을
확인해야 하고 나중에 바뀌면 손실이나 분쟁이 생기는가**입니다.

| 분야 | 남길 기록 | 체인을 쓰는 이유 |
|---|---|---|
| 금융·증권 거래 | 주문 계획·BOSS 승인·체결 지문의 묶음 | 사후 거래 감사와 분쟁 대비 |
| 헌법·상속 | 자비스 버전·정책 변경·승인 시각 | 가족에게 전달할 기준 버전 증명 |
| 모델·스킬 공급망 | 모델 해시·시험 결과·배포 버전 | 어떤 모델이 실제 실행됐는지 확인 |
| 여러 자비스 노드 | 노드 서명·질문·답변·결과 지문 | 서로 다른 컴퓨터의 기록을 대조 |
| 동의·권한 | 동의 버전·철회 시각·권한 범위 | 언제 어떤 범위가 허용됐는지 증명 |

반대로 개인 메모, 음성, 임베딩, 비밀번호, 원본 금융자료는 체인에 올리지
않습니다. 법률상 유언·공증이나 금융기관의 공식 기록을 블록체인이 자동으로
대신하는 것도 아닙니다.

## CodePlan과 로컬 모델 분업

LLM이 사람용 문장을 출력하고 다시 그 문장을 코드가 파싱하는 이중 변환은
느리고 불안정합니다. JARVIS에서는 **로컬 모델이 CodePlan을 만드는 설계자**이고,
**하네스가 검증·컴파일·실행하는 실행자**입니다.

- **반사 통로:** 소형 로컬 SLLM이 의도·엔티티를 분류하고 검증된 `skill_id`를 선택합니다.
- **설계 통로:** 강한 로컬 오픈 웨이트 모델이 복잡한 코드 설계·리팩터링·테스트 계획을 만듭니다.
- **교사 통로:** 로컬 확신도가 낮거나 테스트가 반복 실패할 때만 비식별화한 계획을 클라우드 모델이 비평합니다.

CodePlan은 저장소·브랜치·파일·심볼·수정 이유·테스트·제약·capability를
포함하는 타입화된 계획입니다. 하네스는 `repo.search/read/patch/test/diff/rollback`
같은 도구만 허용하고, 자유 문장을 셸 명령으로 재해석하지 않습니다.

### Agent Supervisor: 하네스의 통제 계층

Agent Supervisor는 하네스에 통합된 운영 계층이지만 보호된 별도 프로세스로
실행합니다. 대화하는 또 하나의 자비스가 아니라, 에이전트를 등록·실행·감시·중지하고
CPU·GPU·메모리·실행 시간·heartbeat(생존 신호)를 제한하는 관리자입니다.
권한 중개기와 Supervisor는 하네스 안의 형제 통제 계층입니다. Supervisor가 더 높은
권한을 갖는 것이 아니며, capability를 만들고 발급하는 일은 권한 중개기만 담당합니다.

한 컴퓨터에는 Supervisor 하나와 JARVIS Orchestrator 하나를 둡니다. Supervisor는
추론 게이트웨이, Agent Bus, MCP Host, 각 Worker를 관리하고, Orchestrator는 목표와
계획을 만듭니다. 실제 부작용 권한은 Authority Broker만 발급하며, 에이전트끼리의
질문이나 합의는 권한이 되지 않습니다. 로컬 MCP는 가능하면 자식 프로세스 `stdio`로,
원격 MCP는 인증된 HTTP로 연결하고, 내부 메시지는 자유 문장이 아닌 타입이 정해진
JSON으로 보냅니다.

읽기·검색·독립 테스트는 병렬로 처리하고, 같은 파일의 쓰기만 직렬화합니다.
작은 반복 작업은 SLLM이나 codemod가 맡으며, 새 아키텍처·낮은 확신도·반복
실패만 강한 로컬 모델이나 선택적 클라우드 교사로 올립니다. 모델은 직접
관리자 셸·파일·금융 권한을 갖지 않습니다.

## 개발 원칙

1. 모든 일반 개발·수정·테스트 커밋은 `develop`에서 수행합니다.
2. `main`은 기준선/검증 이력으로 보존합니다.
3. 대화 원문, PCM, 화면 픽셀, 정확한 좌표, API 키를 Git에 저장하지 않습니다.
4. 기본 음성 경로는 로컬 STT·로컬 TTS입니다. 로컬 대화 경로를 우선하고, 오디오와 임시 전사는 기본적으로 장치 밖으로 보내지 않습니다.
5. Gemini Live 같은 클라우드 실시간 음성은 BOSS가 세션별로 명시적으로 선택·승인한 경우에만 사용합니다. 로컬에서 클라우드로 몰래 전환하거나, 거부된 경로를 자동 재시도하지 않습니다.
6. 결제·예약·삭제·전송 등 외부 부작용은 명시적 승인 또는 BOSS가 미리 적은 좁은 규칙 없이는 실행하지 않습니다.

### 자비스의 사전 검사와 요청 권한

자비스는 필요한 작업을 발견하면 먼저 헌법 버전, 위험·데이터 등급, 대상,
capability, 만료, 예산, 되돌릴 방법, 기존 정책과의 충돌을 검사합니다. 그 결과가
허용 범위면 실행하고, 범위가 부족하면 BOSS에게 사전 승인 또는 반복 정책을
요청합니다. 헌법과 충돌하면 실행하지 않고, 영향·위험·대안을 담은 규칙 수정안만
제안합니다. 헌법상 금지된 예외를 요구할 수는 없습니다.

요청에는 `request_id`, `kind`, `reason`, `target`, `scope`, `risk`, 현재 정책 버전,
`proposed_diff`, 만료, rollback, 근거를 넣습니다. BOSS가 승인한 뒤에만 Authority
Broker가 새 버전과 짧은 capability를 발급하고, Agent Supervisor가 실행합니다.
거절된 요청을 반복하지 않으며, 실제 헌법 변경은 BOSS 재인증·서명, 새 버전,
적용 시각, 회귀시험을 남긴 뒤 활성화합니다.

### 에이전트 루프 권한과 실행 절차

주기 실행은 단순한 타이머가 아니라 BOSS의 사전 정책 또는 새 승인을 담은
`Recurring Loop Lease`가 있어야 합니다. 자비스는 루프를 기획·제안할 수 있지만
스스로 활성화하거나 범위를 넓힐 수 없습니다.

```text
PROPOSED → PREFLIGHTED → APPROVAL_PENDING → APPROVED/GRANTED
→ SCHEDULED → RUNNING → VERIFIED → EXPIRED/REVOKED/PAUSED/FAILED/KILLED
```

Lease에는 `loop_id`, 주기, 최대 횟수·시간·예산, 대상·허용 도구, 데이터 등급,
승인 방식, 정책 버전, 만료, 실패 동작, `kill_handle`을 담습니다. 매 회차마다
Supervisor가 정책과 대상을 다시 확인하고, Authority Broker의 짧은 capability와
heartbeat·timeout 안에서만 Worker를 실행합니다. 검증된 post-condition이 확인된
경우에만 다음 회차를 예약합니다. BOSS는 전체 또는 특정 루프를 언제든 중지할 수
있고, Broker는 만료·철회·정책 충돌 시 권한을 폐기하며, Supervisor는 자원 초과·
반복 실패·대상 변경 시 루프를 격리합니다. 정책이 바뀌면 기존 Lease를 자동
승계하지 않고 재검사와 새 승인을 받습니다.

## 자비스의 선제적 정리와 금융 안전

자비스는 사용하지 않는 구독, 만료될 쿠폰·포인트, 거의 쓰지 않는 계좌,
투자 후보를 먼저 찾아 **알리고 준비**할 수 있습니다. 그러나 계좌 폐쇄,
출금·이체, 증권 주문처럼 되돌리기 어렵거나 돈이 움직이는 행동은 현재 거래
내역과 BOSS 정책을 다시 확인한 뒤에만 실행합니다. 자동화의 목표는 사람에게
매번 묻는 것이 아니라, BOSS가 정한 범위 안에서만 질문을 줄이는 것입니다.

비밀번호와 패스키는 LLM의 문맥이 아니라 운영체제 인증기·로컬 자격증명 저장소가
관리합니다. 자비스는 원문 비밀 대신 계정 별명과 짧은 능력 토큰만 받고, 금융 도구는
조회·초안·실행을 분리합니다. CAPTCHA·2차 인증·신원 확인은 우회하지 않습니다.

## 장기기억 공개 설계

장기기억은 단기·중기·장기 투영과 사실 원장을 하나의 온톨로지 계약으로 연결합니다.
각 항목에는 출처·시점·확신도·민감도·만료·수정 이력이 붙고, 기억 자체에는 실행·승인
권한이 없습니다. 벡터 색인은 원본의 대체물이 아니라 검색용 투영이며, 오래된 추정과
현재 확인된 사실을 구분해야 합니다. 원문 음성·PCM·화면 픽셀·가족 자료는 공개 저장소에
넣지 않고, 공개 예시는 합성·비식별 데이터만 사용합니다. 상세한 내보내기·정정·삭제·
초기화 계약과 검증 한계는 `VOICE_MEMORY_INTEGRATION.md`에서 관리합니다.

설치·운영 방법은 `windows-package/README.md`를 참조하세요.

설치본을 시작하면 설계도의 색상·곡선 언어를 따른 진한 하늘색 항상 위 타원형 음성
상태 데몬이 화면에 표시됩니다. 로컬 진단용 API는 진단 전용으로만 동작하며 브라우저를
자동으로 열지 않습니다. 화면의 `LIVE VOICE STATE`에는 현재 상태를 작은 영문으로,
`LIVE STT PREVIEW`에는 현재 턴의 임시 인식 결과를 표시하며 원문은 저장하지 않습니다.
타원만 잠시 숨기거나 다시 보이게 하려면 전역 단축키 `Ctrl+Alt+J`를 누르세요.
