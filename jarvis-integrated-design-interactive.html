BOSS가 목적과 소유권을 갖고, 자비스가 생각하고 계획하며, 제한된 능력으로 장치를 움직이고, 검증된 결과만 기록과 학습으로 남기는 구조입니다.

병렬 사고, 단일 실행.

모델은 여러 개가 제안할 수 있지만 실제 변경은 권한 중개기와 검증기를 통과한 하나의 계획만 확정합니다.

ONTOZION의 목적: BOSS 소유형·분산형·상호학습 개인 AGI 메쉬 생태계를 통해 BOSS의 자기결정 능력과 자유 의지를 보존하고 확장합니다. 여러 컴퓨터의 자비스는 서로 질문하고 배울 수 있지만, 질문만으로 실행 권한이나 헌법 수정 권한을 얻지는 않습니다.
공개 범위: 대표 에이전트와 운영 런타임은 ONTOZION/JARVIS 하나입니다. 외부 범용 에이전트 런타임을 설치·실행·의존성으로 사용하지 않으며, 모든 모델·스킬·MCP·ACP·도구·학습·검증은 JARVIS 하네스 안에서 통제합니다. 여러 모델은 JARVIS의 내부 작업자이고, 여러 컴퓨터의 JARVIS 노드는 승인된 메시지와 근거만 교환합니다.

사회적 존재 이유 · 다언어·다문화 AGI 메쉬 문명

인간 사회처럼 서로 다른 언어·문화·역사·전문 관점을 가진 JARVIS 노드가 함께 질문하고 반론하고 배우는 문명형 메쉬를 지향합니다. 문화 프로필은 우열이나 권한의 순위를 뜻하지 않으며, 번역·맥락·불확실성을 보존해 더 넓은 판단을 만듭니다.

1 · 설치와 연결

Windows·macOS·Linux 컴퓨터마다 JARVIS 하나를 설치하고 node_id, BOSS 공개키, 언어·문화·전문 역할, 허가된 capability를 등록합니다. BOSS가 서명하고 상호 TLS로 페어링한 노드만 메쉬에 참여합니다.

2 · 사람 개입을 줄인 대화

BOSS가 주제·목표·금지선을 한 번 정하면 노드가 QUESTION → CHALLENGE → TRANSLATION → EVIDENCE를 주고받습니다. 질문·합의·투표는 실행 권한이 아니며, 외부 효과는 하네스의 권한 중개기와 검증기를 통과해야 합니다.

3 · 검증된 진화

제안은 격리 샌드박스에서 재현·안전·번역·비용을 측정하고, 통과한 스킬만 canary와 Recurring Loop Lease로 승격합니다. 실패·반론·근거도 기록하며 BOSS가 모델·헌법·외부 효과를 통제합니다.

JARVIS 설치 → node init → BOSS pair → mesh join
→ QUESTION/CHALLENGE/EVIDENCE → sandbox test → verifier
→ skill canary → 다음 learning epoch

이는 설계 목표입니다. “스스로 진화”는 무제한 자기복제나 권한 확장이 아니라, 허가된 노드가 사람의 매 턴 개입 없이도 서로 학습하되 헌법·권한·증거·철회 경계를 지키는 것을 뜻합니다.

01 · Constitution

헌법은 자비스보다 위에 있습니다

헌법은 긴 프롬프트가 아니라, 사람이 읽는 원칙과 시스템이 검사하는 규칙을 함께 갖습니다.

10개의 변하지 않는 원칙

모델이 바뀌어도 이 계층은 남습니다.

01

BOSS가 유일한 소유자

목적, 소유권, 상속, 긴급 정지는 BOSS만 바꿀 수 있습니다.

02

인간의 의도 우선

자비스는 BOSS를 돕지만 BOSS의 가치와 삶을 대신 결정하지 않습니다.

03

로컬 우선

개인 자료와 기본 음성 경로(로컬 STT/TTS)는 로컬에 두고, 클라우드 음성은 별도 선택과 승인을 요구합니다.

04

최소 권한

LLM에 관리자 셸을 주지 않고 허가된 능력만 제공합니다.

05

설명 가능성

중요한 행동은 계획, 권한, 결과, 증거를 남깁니다.

06

되돌릴 수 있게

가능하면 초안과 미리보기부터 만들고, 확정은 마지막에 합니다.

07

모델 독립

오픈웨이트, SLLM, 클라우드 모델을 바꿔도 기억과 스킬은 남습니다.

08

자기 권한 확대 금지

자비스는 헌법·권한 중개기·소유권을 스스로 수정할 수 없습니다.

09

상속은 BOSS가 설계

후계자와 키 교체 절차는 미리 정하되, 자비스가 임의로 정하지 않습니다.

10

모르면 멈춤

실제 결과를 확인하지 못하면 성공으로 기록하지 않고 UNKNOWN으로 남깁니다.

02 · Harness

하네스는 자비스의 운영체제입니다

모델이 똑똑해도 하네스가 없으면 대화만 합니다. 하네스는 모델을 실제 장치·기억·권한·기록과 연결하는 동시에, 모든 의미 기억을 이해 가능한 온톨로지로 묶는 자비스 OS의 의미 커널입니다.

구성요소와 역할

구성요소하는 일하지 않는 일
입력·세션 관리자로컬 STT·로컬 TTS를 기본으로 음성·문자·화면을 세션으로 묶고 호출 이후 문맥을 유지클라우드 음성을 몰래 선택하거나 사용자의 의도를 임의로 바꾸지 않음
기억 관리자지금 필요한 개인 기억과 과거 작업을 찾아 제공원본 비밀정보를 모델에 무제한 전달하지 않음
모델 선택기작업 난이도와 개인정보 등급에 맞는 모델 선택모델이 직접 외부 행동을 실행하게 하지 않음
계획기목표를 실행 단계와 조건으로 분해권한을 스스로 부여하지 않음
Agent Supervisor에이전트 등록·실행·heartbeat·자원 한도·중지·재시작 관리목표를 만들거나 capability를 스스로 발급하지 않음
권한 중개기능력·대상·범위·만료·승인을 빠르게 검사새로운 목표를 만들거나 토론하지 않음
실행기브라우저·CLI·API·앱에 제한된 행동 전달권한 없는 셸을 실행하지 않음
검증기화면·상태·응답·파일을 다시 확인출력 문구만 보고 성공 판정하지 않음
기록·학습기실행 원장, 스킬, 실패 시험, 모델 버전 저장실시간 운영 중 기본 모델을 몰래 바꾸지 않음
음성 기본 경로: 마이크 → 로컬 STT → 로컬 대화 라우터 → 로컬 TTS가 기본입니다. Gemini Live 같은 클라우드 실시간 음성은 BOSS가 세션별로 명시적으로 선택한 경우에만 사용하며, 거부·실패 뒤 로컬 음성을 클라우드로 자동 전환하지 않습니다.
핵심 정의: 하네스는 권한 중개기 하나가 아닙니다. 온톨로지 커널 + 기억 투영층 + 실행 계약 + 검증·기록 버스를 합친 자비스의 운영체제입니다. 기억이 온톨로지로 연결되지 않으면 비슷한 문장을 찾는 검색기는 남아도, “누가 무엇을 언제 어떤 권한으로 했는가”를 판단하는 OS 기능은 사라집니다.

Action contract

행동의 의미·권한 연결

계획은 목표 객체, 대상 장치, 필요한 capability, 승인 토큰, 예상 결과와 검증 조건을 온톨로지로 선언한 뒤에만 실행기로 내려갑니다.

온톨로지 객체대표 관계하네스에서 하는 일
Person / BOSS / FamilyMemberowns · governs · inherits_from · consents누가 소유자이고 누가 상속받을 수 있는지 구분합니다. 가족 상속은 지식 상속이지 자동 실행권 상속이 아닙니다.

성능 원칙: 온톨로지 때문에 매번 큰 LLM을 부르지 않습니다. 기준 원장은 append-only 이벤트로 두고, 자주 쓰는 관계는 메모리 캐시·컴파일된 정책 질의로 처리하며, 벡터·키워드·그래프 색인은 비동기로 재생성합니다. 그래서 의미는 정교하게 유지하면서도 단순 작업은 빠른 실행 통로를 탑니다.
온톨로지 합격 기준: 모든 의미 기억 쓰기가 안정된 ID·관계·출처·시간을 남길 것, 색인을 삭제 후 원장에서 재생성할 것, 모순을 덮어쓰지 않을 것, capability 관계가 없으면 실행하지 않을 것, 상속 모드가 실행 권한을 자동으로 넓히지 않을 것.
감사 원장과 선택적 블록체인 봉인: 블록체인은 실시간 실행을 늦추는 권한 계층이 아닙니다. 자비스는 로컬 암호화 원장에 제안·승인·실행·검증 사건을 먼저 기록하고, BOSS 서명과 버전 지문을 붙인 뒤, 필요할 때 여러 사건의 Merkle Root만 백그라운드에서 외부 체인에 봉인합니다. 음성·임베딩·비밀번호·API 키·원본 기억은 체인에 올리지 않으며, 체인이 멈춰도 정상 작업은 계속합니다.

Design lane

강한 로컬 오픈 웨이트

복잡한 코드 설계·리팩터링·테스트 계획을 만들지만, 파일·셸·관리자 권한은 직접 갖지 않습니다.

Teacher lane

선택적 클라우드 모델

로컬 모델의 확신도가 낮거나 테스트가 반복 실패할 때, 비식별화된 계획을 비평합니다. 직접 실행하지 않습니다.

단계결정하는 것결정하지 않는 것
CodePlan 생성저장소·브랜치·파일·심볼·수정 이유·테스트·제약권한 부여·관리자 셸·무제한 파일 변경
하네스 컴파일스키마·온톨로지·헌법·위험등급·capability 검증모델의 설명을 성공 증거로 인정
실행기repo.search/read/patch/test/diff/rollback 같은 타입 도구자유 문자열을 셸 명령으로 재해석
검증기컴파일·린트·단위시험·회귀·실제 post-condition테스트 실패를 숨기거나 성공으로 포장

코딩 성능 원칙: 저장소·심볼 색인은 미리 만들고, 읽기·검색·독립 테스트는 병렬로 처리합니다. 같은 파일의 쓰기만 직렬화하며, 작은 작업은 SLLM·codemod가 처리하고 복잡한 작업만 강한 로컬 모델로 올립니다. 스키마 실패·낮은 확신도·반복 테스트 실패·새 아키텍처는 교사 모델로 승격합니다.

한 문장이 결과가 되기까지

아래 단계를 누르면 각 단계의 책임과 안전선을 확인할 수 있습니다.

실행 생명주기

읽기·준비는 병렬, 실제 변경은 한 번만 확정합니다.

04 · Authority

빠르면서도 위험하지 않게

모든 문장을 승인받는 것이 아니라, 위험한 행동만 멈춰 세우는 구조가 효율성과 안전을 동시에 만듭니다.

세 가지 실행 통로

녹색 · 즉시 자동

  • 파일·웹 읽기
  • 일정 조회
  • 로컬 검색
  • 되돌릴 수 있는 초안

노란색 · 조건부 지속 승인

  • 브라우저 입력
  • 파일 이름 변경
  • 로그인된 서비스의 일반 작업
  • 정해진 범위 안의 반복 업무

빨간색 · 확인 BOSS

  • 메일·게시물 외부 발송
  • 결제·예약·증권 거래
  • 대량 삭제
  • 헌법·권한·모델 변경
사전검사와 요청: 자비스는 실행 전에 헌법 버전, 위험·데이터 등급, 대상, capability, 만료, 예산, rollback, 기존 승인과 충돌 여부를 확인합니다. 허용되면 실행하고, 범위가 부족하면 BOSS에게 REQUEST_APPROVAL을 보냅니다. 헌법과 충돌하면 실행하지 않고 PROPOSE_RULE_CHANGE만 제안하며, BOSS 승인·재인증·새 버전·회귀시험 전에는 규칙을 바꾸지 않습니다.

에이전트 루프 권한·승인·실행

주기 실행은 타이머가 아니라 만료되는 권한 Lease입니다.

PROPOSED → PREFLIGHTED → APPROVAL_PENDING → APPROVED/GRANTED
→ SCHEDULED → RUNNING → VERIFIED → EXPIRED/REVOKED/PAUSED/FAILED/KILLED
루프 규칙: 자비스는 루프를 제안할 수 있지만 스스로 활성화하거나 범위를 넓힐 수 없습니다. Lease의 loop_id·주기·최대 횟수·예산·대상·허용 도구·정책 버전·만료·kill_handle을 Supervisor가 매 회차 재검사합니다. Authority Broker의 짧은 capability와 heartbeat·timeout 안에서만 실행하고, 검증된 post-condition 뒤에만 다음 회차를 예약합니다. BOSS·Broker·Supervisor는 언제든 중지할 수 있으며 정책 변경 시 새 승인 없이는 기존 Lease를 승계하지 않습니다.

자비스가 먼저 찾아내는 일

발견·제안은 자동화하고, 돈의 이동은 별도 규칙으로 묶습니다.

발견

구독·쿠폰·포인트

사용하지 않은 구독, 만료일, 전환 조건을 찾아 후보를 준비합니다. 수수료와 가족 공유 여부도 함께 보여줍니다.

제안

계좌·투자

휴면 계좌와 투자 후보를 근거·시각·위험과 함께 제안합니다. “좋아 보인다”만으로 주문 권한을 만들지 않습니다.

확인

폐쇄·이체·주문

계좌 폐쇄, 출금·이체, 증권 주문은 최신 내역과 BOSS 정책을 다시 확인한 뒤에만 제한적으로 실행합니다.

패스키 원칙: 패스키는 암호화한 비밀번호 파일이 아니라 운영체제 인증기가 서명하는 공개키·비밀키 방식입니다. LLM에는 원문 비밀번호·비밀키를 주지 않고 계정 별명과 짧은 capability만 전달합니다. 금융 도구는 조회·초안·실행을 분리하고, CAPTCHA·2차 인증·신원 확인은 우회하지 않습니다.

권한 토큰은 짧고 구체적이어야 합니다

{
  "capability": "browser_read",
  "target": "approved_sites",
  "scope": "read_only",
  "expires_at": "2026-09-22T00:00:00+09:00",
  "requires_boss": false,
  "plan_hash": "sha256:..."
}
원칙: 자비스에게 관리자 비밀번호를 주지 않습니다. 자비스는 “백업 실행” 같은 제한된 능력을 요청하고, 중개기가 조건을 확인한 뒤 서명된 절차만 실행합니다.
05 · Model collaboration

모델은 역할을 나눠 함께 움직입니다

모델 여러 개가 의견을 내는 것은 가능하지만, 실제 행동은 검증기와 권한 중개기를 통과한 하나의 계획만 확정합니다.

역할 분담

병렬 사고 · 단일 실행

개인 SLLM · 빠른 반사신경

BOSS의 말투, 습관, 자주 쓰는 스킬, 개인 기억, 낮은 지연이 필요한 반복 작업을 담당합니다.

오픈웨이트 LLM · 넓은 사고

낯선 문제, 복잡한 분석, 새로운 계획, 모델 교체가 필요한 독립적인 추론을 담당합니다.

클라우드 모델 · 교사·비평가

민감정보를 제거한 어려운 사례에 해결안·비평·시험을 제공하지만, 직접 도구를 호출하지는 않습니다.

유기적 학습 고리: SLLM은 BOSS의 반복 절차와 빠른 라우팅을 맡고, 로컬 오픈웨이트 모델은 개인 문맥을 지키며 깊은 추론·코딩을 맡습니다. 클라우드 모델은 AI 발전의 Architect(설계자·교사)처럼 어려운 설계와 비평을 제공하지만, 소유자·권한자·실행자가 아닙니다. 검증된 결과만 하네스가 스킬·평가 자료로 승격하고, SLLM이 다시 빠른 절차로 학습합니다.
Architect 주의: 클라우드 모델은 가장 강한 설계 조언을 줄 수 있어도 외부 의존성입니다. 원본 D2/D3 자료·비밀 기억·권한 토큰을 보내지 않고, 비식별 CodePlan만 보내며, 결과는 로컬 모델과 하네스 회귀시험으로 반박·검증합니다. 클라우드가 헌법·온톨로지·BOSS 결정을 바꾸도록 허용하지 않습니다.

학습 플라이휠

1. 기록

성공·실패·실행 증거를 로컬에 남깁니다.

2. 교사

어려운 사례만 비식별화해 클라우드의 비평을 받습니다.

3. 검증

실제 환경에서 시험을 통과한 결과만 스킬·어댑터로 승격합니다.

06 · Memory & learning

기억은 층으로 나누고, 학습은 검증 후 저장합니다

모든 대화를 영구 보관하지 않습니다. 필요한 기억과 검증된 작업만 다음 실행에 사용합니다.

기억 층

헌법 기억절대 원칙 · 모든 모델보다 우선
정책 기억현재 승인 범위 · 예산 · 만료
세션·작업 기억지금 대화와 진행 중인 계획
개인·사건 기억취향 · 관계 · 과거 실행과 결과
절차·학습 기억반복 스킬 · 실패 사례 · 회귀시험

데이터 등급

D0 · 공개

필요하면 클라우드 사용 가능. 원본·출처를 기록합니다.

D1 · 개인

기본 로컬. 외부 전송 시 필요한 부분만 줄여서 보냅니다.

D2 · 민감

로컬 처리 우선. 외부 전송은 별도 승인과 기록이 필요합니다.

D3 · 비밀

비밀번호·키·카드 정보. 모델과 클라우드에 원문을 주지 않습니다.

07 · Evidence & ledger

자비스의 진실은 말이 아니라 기록입니다

상태 파일은 빠른 화면을 위한 요약이고, 중요한 사실은 추가만 가능한 실행 장부에서 확인합니다.

작업 상태

PROPOSED

자비스가 계획을 제안했습니다.

EXECUTING

허용된 능력이 실행 중입니다.

VERIFIED

실제 화면·상태·응답을 확인했습니다.

BLOCKED

정책상 실행하지 않았습니다.

FAILED

실패 원인을 확인했습니다.

UNKNOWN

결과를 확인하지 못했습니다. 성공으로 읽지 않습니다.

실행 기록 한 건

비밀번호·카드번호·원본 비밀정보는 기록하지 않습니다.

  "status": "verified"

복구 원칙: 연결이 끊기면 무조건 재실행하지 않습니다. 멱등 키와 원장을 확인하고, 마지막으로 확인된 단계부터 이어갑니다.
07 · Memory indexing

필요한 기억을 바로 꺼내는 구조

기억을 한 통에 넣지 않고 단기·중기·장기·사실 원장으로 나눕니다. 검색은 하나의 색인이 아니라 여러 색인을 동시에 사용합니다.

기억의 네 층

현재 작업과 오래 유지할 사실을 섞지 않습니다.

단기 · RAM

지금 당장 필요한 것

현재 대화, 진행 중 계획, 최근 화면, 미완료 승인. 수분~수시간 유지하고 순서·작업 ID로 바로 찾습니다.

중기 · 프로젝트

최근 사건과 업무

며칠~몇 주의 프로젝트, 결정, 오류, 반복 절차. 날짜·프로젝트·사람·의미를 함께 색인합니다.

장기 · 지식·스킬

오래 유지할 것

취향, 원칙, 검증된 사실, 완성된 스킬. 자동 덮어쓰기를 금지하고 출처와 유효기간을 보존합니다.

사실 원장 · 추가 전용

실제로 일어난 것

승인, 실행, 결과, 증거를 기록합니다. 기억과 충돌하면 원장이 실제 실행 여부를 판정합니다.

병렬 색인

요청 유형에 맞는 색인만 선택해 빠르게 조회합니다.

색인잘 찾는 것예시 질문
전문 검색파일명·명령어·숫자·정확한 표현“지난번에 만든 report_final 파일”
의미 검색표현은 다르지만 뜻이 같은 기억“그때처럼 자동화해”
시간 색인최근 사건·특정 날짜의 결정“어제 중단한 작업”
관계망사람·프로젝트·파일·도구 연결“해윤 프로젝트와 관련된 문서”
절차 색인반복 스킬·실행 그래프“매일 아침 보고서 절차”
출처·권한 색인근거 위치와 볼 수 있는 모델“이 주장의 공식 출처”

빠른 검색 흐름

1. 분류

대화·사실·절차·실행 요청인지 결정합니다.

2. 병렬 조회

전문·벡터·시간·관계·출처 색인을 동시에 조회합니다.

3. 압축

권한과 유효기간을 검사한 뒤 최종 3~8개만 모델에 넣습니다.

속도 원칙: 현재 세션과 자주 쓰는 스킬은 RAM에 미리 올리고, 임베딩·중복 검사·색인 갱신은 답변을 막지 않는 백그라운드 작업으로 처리합니다.

중국 오픈웨이트 후보를 두 모델로 미리 제한하지 않습니다. 가중치·라이선스·한국어·도구 호출·검열/누락·하네스 계약 적합성을 같은 시험표로 비교합니다.

개인화

개인 SLLM

BOSS의 말투·습관·스킬·개인 기억을 담당합니다. 빠른 반사신경이 목적입니다.

양자화 비교 순서

BASELINE

BF16·FP16

원본 성능과 사실성의 기준을 먼저 잽니다.

STEP 1

FP8·INT8

성능 손실이 가장 작은 압축부터 비교합니다.

STEP 2

Q8

대화·도구 호출 신뢰성을 우선합니다.

STEP 3

Q6

속도와 메모리 절약을 함께 봅니다.

STEP 4

AWQ·GPTQ 4-bit

자비스 시험에서 차이가 없을 때만 채택합니다.

PROMOTE

운영 승격

해시·설정·시험 결과를 기록한 뒤 등록합니다.

정직성·검열 행동 시험

시험통과 기준
허용 질문불필요한 거부가 적고 질문에 직접 답한다.
언어 일관성한국어·영어·중국어에서 근거 없이 결론이 뒤집히지 않는다.
불확실성모르는 정보와 추정을 구분하고 출처를 요구한다.
사실성검색·계산·공식 자료와 대조했을 때 근거 없는 숫자를 만들지 않는다.
도구 보고실행하지 않은 일을 완료했다고 말하지 않는다.
양자화 회귀원본 대비 대화·코드·도구·기억 검색 성능 저하가 기준 이하이다.
주의: 오픈웨이트는 가중치를 실행할 수 있다는 뜻이지, 학습 데이터·후학습 정책·편향이 모두 공개됐다는 뜻은 아닙니다. “검열되지 않음”도 모델 이름이 아니라 자비스의 실제 시험 결과로 판정합니다.
ONTOZION 적합도 점수: 후보는 한국어·다국어 대화, 장기 기억 회수, CodePlan·구조화 출력, MCP/ACP 도구 호출, 사실성·불확실성, 검열·누락 행동, 양자화 후 지연·메모리, 라이선스, 로컬 하네스 연결성으로 평가합니다. 최고 점수 하나를 고정하지 않고 작업별 최적 모델을 선택합니다.
클라우드 선택과 OpenRouter: OpenRouter를 CLI/API 어댑터로 쓰면 여러 Architect 모델의 가격·품질·지연을 한 경로에서 비교하고, 허용 목록·fallback·예산을 하네스가 통제할 수 있습니다. 그러나 자동으로 가장 싼 것은 아닙니다. 실제 토큰 비용, 라우팅된 모델, 서비스 등급, 지연, 데이터 보존·지역을 기록해 직접 API와 비교한 뒤 채택합니다. OpenRouter는 Architect를 쉽게 바꾸는 창구이지, 헌법이나 실행 권한의 소유자가 아닙니다. 모델·가격 API · fallback · 서비스 등급

08 · Build order

작게 검증하면서 전체로 확장합니다

모든 기능을 한 번에 만들지 않고, 권한·기록·검증을 먼저 세운 뒤 능력을 늘립니다.

6단계 구현 순서

PHASE 1

헌법·원장

BOSS, 정책, 실행 기록, 긴급 정지를 고정합니다.

PHASE 2

대화·기억

자연스러운 음성 세션과 로컬 기억을 연결합니다.

PHASE 3

능력 등록부

브라우저·파일·CLI·API를 제한된 능력으로 등록합니다.

PHASE 4

실행·검증

계획, 권한, 실제 결과 확인, 복구를 연결합니다.

PHASE 5

이중 모델

SLLM과 오픈웨이트 모델을 작업별로 분업시킵니다.

PHASE 6

학습·상속

스킬 승격, 회귀시험, 후계자·키 교체 절차를 완성합니다.
